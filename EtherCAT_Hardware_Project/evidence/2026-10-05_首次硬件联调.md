## 3. 两个实测中修复的问题

**SDO 没有发出：主站缓存与真实状态不同。** 最初发现从站后 SDO 1018:01 返回 wkc=0，但 GDB 显示 SPI 正常、主循环运行。这并非网络断开。SOEM 2 的 Mailbox 发送检查 `slavelist[1].state`；`ecx_statecheck(..., 0, PREOP, ...)` 更新的是虚拟汇总站 0，实际站缓存仍可能为 INIT。主站现在等待 PREOP，再用 `ecx_readstate` 刷新实际站状态，确认站 1 为 PREOP 后才发 SDO。修复后的 Inspect 和全部演示均通过。

**跨会话 Reset 后仍有故障：再次停止 PDO 会重新超时。** 第一轮演示通过，主站退出停止发送；板端锁存 FF04。单独 Reset 成功后该进程也退出，之后打开新 Demo 时可能又已超时。失败复跑的 WKC 仍为 3，但 sw=0x0008，证明“通信成立”和“关节允许使能”是不同条件。

加入显式 `--reset-start` / PowerShell `-ResetBeforeDemo`，在同一个 OP 会话先复位，再继续演示，复跑两轮均通过。默认启动不自动复位，演示中出现意外故障仍会中止。此选项是用户明确要求复位的操作，不是恢复连接就自动使能。

失败记录保留为 `20261005_first_inspect.txt`、`20261005_inspect_preop_wait.txt`、`20261005_demo_repeat.txt/.csv`；它们不混入成功样本统计。修复代码位于 `master/joint_master.c` 与 `tools/master.ps1`。

## 5. GDB 与最终状态

演示退出后的独立板端观察：`state=JD_FAULT`、`error_code=65284 (0xFF04)`、`velocity=0`，`timeout_count=3`；ESC 应用状态为 INIT。最后接收时间 380421887µs，观察时更新为 387937574µs。该快照证明退出后已处理超时，不能据此声称精确测到 100ms 动作点，也不是物理拔线实验。

RCC_CR/PLLCFGR/CFGR 为 `0x03035e83 / 0x07405408 / 0x0000940a`，结合商家 8MHz HSE 配置推算 SYSCLK=168MHz。TIM5 PSC=`0x53`，对应 1MHz 计数；未使用仪器测频。当前 ELF 没有 `SystemCoreClock` 符号，手册已改为读取寄存器。本机 GDB 打印 model 类型会给出 CP1252 转换警告，但字段实际可读。

收尾已 `reset run`，暂停核对后恢复并 detach：`nAlStatus=INIT`，`state=JD_DISABLED`、statusword=0x0040、位置/速度/错误码均为 0，尚未接收新 PDO。仅关闭本次启动、核对路径的 OpenOCD 进程；MCU 留在运行状态，有线口仍为 Up/100Mbps。日志为 [最终复位记录](logs/20261005_final_reset.txt)。

## 6. 当前可复现入口

在本项目文件夹打开 PowerShell，关闭其他占用该网卡的 EtherCAT 主站：

```powershell
$nic = '\Device\NPF_{52528361-DC95-49EC-95CF-1D2653888A6F}'
.\tools\master.ps1 -Action Inspect -Interface $nic
.\tools\master.ps1 -Action Demo -Interface $nic -ResetBeforeDemo -PeriodUs 10000 -Csv 'evidence/logs/run_next.csv'
& 'D:/apps/Python3.10.11/python.exe' tools/analyze_log.py evidence/logs/run_next.csv
```

预期有 `SDO ... match`、`OP reached; expected WKC=3`、`reset status=0x0040 velocity=0`、`demo result=PASS ... checks=0x3f`。`Cycles=2000` 是上限，不是必须跑满，序列完成后提前退出。本次固件已烧录，未改源码时无需重新下载。

接下来学习先沿一条链路解释：主站目标位置 → 12 字节 RxPDO → LAN9252 → SPI/SSC → MCU 模型 → TxPDO 返回。再用日志区分 EtherCAT 的 OP 与 CiA402 的使能状态，最后理解本次 SDO 缓存及 FF04 复位问题。详见 [代码导读](../docs/04_主从通信与代码导读.md)。
