## H01：练习核对与教师批注（2026-10-06）

学习者在聊天中表示“我理解了，我也完成了学习记录里面的问题”，并让教师判断是否进入下一课。教师读取了上面的实际答案；原文保留，不用参考答案替换。判断：整体调用链、最新值缓存与 LED 节奏已理解，可进入 H02；下面几处需要补正。这里的完成仅限本课阅读与练习，不表示学习者独立实现了整个硬件工程。

- A1 正确：板端 main 第 862 行调用 `Project_Poll()`。
- A2：`joint_receive` 是模型接收命令的函数；若问通信入口，则是 `Project_OutputMapping`，它负责解码并发布命令。`joint_update` 与 `Project_InputMapping` 的职责判断正确。
- A3 方向正确：重复目标也能代表新的接收事件；使用最新接收时间判断通信是否继续，不能只等目标变化。目标是否变化和是否收到新数据是两个问题。
- A4：继续更新状态和检查超时的理解正确；“不更新就会超时”需修正。`joint_update` 检查是否超时，`joint_receive` 才刷新接收时间。没有新命令时还要继续处理运动、状态和通信许可；停止调用更新函数可能让故障检查无法运行，并不会自动可靠地报告超时。
- B：快照目标 -1000、调用一次、最终处理版本 10、最新值缓存均正确。取得的 `generation` 应为 **10**；答案中的 **2** 是版本增加量 `10-8`，不是当前版本号。
- C：语句、250ms 亮灭、500ms 一轮、2 轮/秒和 OP 常亮均正确。无需改 PDO 的结论正确，理由应为：只改变板端显示的时间条件，没有改变网络传输字段、偏移和总长度。LED 由模型与通信状态驱动，并非每个显示动作都有一个专门的 PDO 字段。
- D：主线理解符合本课目标。进一步区分“发布反馈到缓存”“映射并交给 ESC”“主站收取”三个环节；LED 更新不必等待电脑已经收到反馈。`Project_Poll` 是功能接入点，较完整的功能可独立成模块再从这里调用。
