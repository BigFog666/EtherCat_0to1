## 简历写法

按目前已验证范围可使用以下描述；长时间测试与物理断线完成后再补充对应数据：

> **STM32F407 + LAN9252 EtherCAT 单轴模拟关节与 SOEM 调试主站**<br>
> 基于商家 SSC 和 SOEM 集成 SPI PDI 从站，使用 CMake/GNU Arm 构建、ST-LINK/OpenOCD 下载与 GDB 调试；完成 CoE 对象读取与 12/12 字节 PDO 映射核对。实现 CiA402 教学子集的 CSP/CSV 模拟运动、快速停止、故障锁存与显式复位，验证真实 OP 通信及主站退出后的超时处理。在 Windows 主站请求 10ms 周期下完成三轮短测、627 次有效 PDO 交换，WKC 均为 3，并保留周期分布与异常诊断记录。

当前可以写“已完成真实主从通信与模拟关节演示”，但还不能写“物理拔线恢复已验证”“长时间稳定运行”“1ms 稳定实时”“DC 多轴同步”“真实关节闭环”或“自主实现完整 EtherCAT 协议栈”。以上仍需学习者能解释实现和诊断过程；代为调通不等于本人已掌握。

面试能讲清这几件事，就比背协议名更有说服力：为什么要 ESC；SPI 与 EtherCAT 是两段不同链路；SDO/PDO 各自的用途；ESI/SII/对象字典为何必须一致；OP 为什么不等于驱动使能；WKC 异常为什么不能信任旧反馈；故障恢复为什么需要复位边沿；Windows 周期指标与板端/总线时延有什么不同。

## 来源和范围

商家原始 SPI IO ZIP、SSC 5.11/ST 标准库的版权与许可说明保留在本地 vendor 源文件中；原 ZIP SHA-256 在 `config/source_manifest.json`。本项目生成器只应用明确补丁，不重写原 ZIP 或原 SDK。

SOEM 固定提交 `88e8ed46efba7dfa7b94d08a512db25a33e3f8d5`，许可证见 `vendor/SOEM/LICENSE.md`（GPLv3 / 商业双许可）。eepromtool 是 SOEM 自带示例，仍归属上游；并非我们自行实现的 EEPROM 协议。发布时按所用依赖许可证处理，不把忽略 vendor 当作免除许可义务。

本版自有内容：CMake/GNU 移植与工具脚本、STM32 启动/链接/堆、SSC 与模型桥接、显式 PDO 编解码、CiA402/关节教学模型、SOEM 演示流程、测试与日志分析。没有重写 EtherCAT 线协议或商家完整协议栈。第一版故障停止是模型停止，不能代替真实驱动保护；原厂 SPI busy 等待未全面加入时限，应用超时也不覆盖 MCU 卡死。
