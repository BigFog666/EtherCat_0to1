# 一个能讲明白、能现场演示的项目

项目启动时的软件主线记录到第十一课，已接触 PDO、对象字典、Mailbox/SDO、SM/FMMU 和 CiA402；课程当前状态仍以上一级 README 与学习记录为准。硬件项目需要把这些概念连接到真实 MCU 下载、LAN9252 的 SPI PDI、主站配置和实测日志。

2026-10-05 已代为完成真实下载、SPI/SDO/OP/PDO 与三轮完整演示，见 [联调记录](../evidence/2026-10-05_首次硬件联调.md)。接下来重点是你亲自复跑、解释通信过程和修改一个参数；物理拔线、抓包和长测还需完成。

建议项目名称：**基于 STM32F407 与 LAN9252 的 EtherCAT 单轴模拟关节控制器及 SOEM 调试主站**。

第一版的完成标准是：PC 扫描到真实板卡，SDO 核对身份/模式/PDO 映射，设备到 OP，主站完成 CiA402 使能、±1000 位置往返、CSV 速度模拟、快速停止、故障注入和显式复位；拔线后从站模型停止并锁存超时，恢复后不会自动使能；保留实际 CSV、状态截图和演示视频。你能解释一次目标位置从 PC 到 STM32 再返回 PC 的全过程。

这比只做“能扫描到从站”更完整；真实电机和多轴同步可作为下一版扩展。第一版位置是教学计数、速度是计数/秒，没有物理编码器。CiA402 教学子集已实现 CSP=8、CSV=9；bit15 是本项目自定义的故障注入，不能推广成商用驱动的通用命令。

## 用几天熟悉的顺序

| 环节 | 做什么 | 到哪里算完成 |
|---|---|---|
| 第一天 | 运行构建与电脑演示；接电/SWD；备份出厂 Flash/EEPROM；认识 CMake 与 GDB | 能说明 ELF/HEX/BIN、Flash/RAM 和 main 入口，能保存实际探针输出 |
| 第二天 | 理解保留出厂 SPI SII 的配置方式与下载过程；扫描、SDO Upload、SAFEOP→OP | 身份和 12/12 字节 PDO 配套，记录实际 AL 状态与 WKC |
| 第三天 | 运行完整主站演示；阅读自己写的应用与主站代码 | 能解释 6→7→15、状态掩码、位置/速度模型、故障复位上升沿 |
| 第四天 | 拔线/恢复试验、重复运行、周期统计、抓包；整理简历和演示 | 用数据回答“主站变慢/断网/状态不匹配时怎么办” |

以上是熟悉项目的顺序，不要求重复已完成的备份或写 EEPROM。板端基础通信已经跑通，可直接从复跑和代码解释开始；遇到配置变化时先核对实读身份、SPI 与对象字典。每天可按自己的时间完成一个环节，不要求重新按原课程逐节等待。

## 从参考工程变成你的项目

先运行，再解释，再做一个小修改。第一轮只修改 `JOINT_MAX_VELOCITY` 或主站目标值，预测到达时间，编译后对比日志。第二轮修改超时阈值并做拔线观察，解释 ESC 看门狗与应用超时的差别。第三轮把一个自己定义的诊断量加入 SDO；再考虑扩展 PDO，此时要同时调整固件映射、编解码、ESI/SII 和主站检查。

每轮保留预测、实际结果和解释。AI 生成参考代码不影响你学习和改进，但简历与面试应明确自己的理解、修改、联调和实测工作，复用库的部分如实说明。
