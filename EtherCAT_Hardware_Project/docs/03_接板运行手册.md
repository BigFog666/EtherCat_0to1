# 接线、构建、烧录、调试和主从通信

本手册针对元杞 V3 / STM32F407ZET6。2026-10-05 已完成真实 SWD、备份、烧录校验、SPI、SDO、OP/PDO 和三轮完整关节演示，详见 [首次硬件联调](../evidence/2026-10-05_首次硬件联调.md)。以下步骤用于复现；出厂备份已完成，不要用新程序覆盖原备份。第一版使用 SPI PDI、CSP/CSV、普通 SM 同步，固件 `DC_SUPPORTED=0`；主站不配置 DC。

## 1. 首次接线

V3 原理图显示 USB 电源的 5V 经过 AMS1117 产生 3V3，SWD 为 PA13/SWDIO、PA14/SWCLK。用板子的 USB 供电接口和现有供电线供电；不要把 5V 接到 3V3/SWD 信号。实际针脚位置以板上丝印及原理图为准，不根据照片方向猜排针编号。

| ST-LINK 信号 | 板端 |
|---|---|
| GND | GND，必须共地 |
| SWDIO | SWDIO / PA13 |
| SWCLK | SWCLK / PA14 |
| VTref（若探针有） | 板端 3V3，作为电平参考；核对探针说明 |
| NRST（可选，有该引脚时） | STM32 RESET/NRST |

板子先独立供电；ST-LINK 的 3V3 输出与 VTref 不是同一概念，不同时用两个输出源给板子供电。BOOT0 保持从 Flash 启动的默认状态。网线从 PC 的 Realtek 有线口直连板的 IN/Port0，另一口暂空，不经过交换机。使用该口时原来的普通网络连接会断开；SOEM 发 EtherCAT 二层帧，无需给板子设 IP。

SPI 内部连线由板上完成：PA8=CS、PA5=SCK、PA6=MISO、PA7=MOSI，PC0=LAN9252 IRQ。当前先不使用 SYNC0/1；不要另接杜邦线到 SPI 信号。若实物版本或配置表与此不符，先核对 PDI，而不是继续改 XML 猜测。

## 2. 电脑构建

在 `EtherCAT_Hardware_Project` 打开 PowerShell：

```powershell
.\tools\build.ps1
.\tools\master.ps1 -Action Offline
.\tools\master.ps1 -Action List
```

CMake 生成 MinGW Makefiles：ARM GNU 13.3 编译板端，MinGW GCC 13.1 编译 Windows 主站。路径在 `config/tool_paths.json`。Npcap DLL 由主站脚本临时加入 PATH，无需复制系统 DLL。初次换电脑需 CMake≥3.28、GNU Arm、MinGW Make、OpenOCD 和 Npcap。

如果 PS 禁止运行本地脚本，可以单次执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1
```

以后改应用源码只需构建。自动生成目录不要直接改；改 `tools/prepare_firmware.py` 再生成。生成器保留商家原始 SDK，遇到原始 SDK 内容被修改会拒绝覆盖。

## 3. 先保存出厂状态

连接 ST-LINK 后，先备份 STM32 Flash：

```powershell
.\tools\flash.ps1 -BackupOnly
```

该操作读取 512 KiB，保存在 `evidence/logs/`，不烧录，但会暂停 MCU；读完后复位或重新上电让原程序运行。若读保护导致读取失败，保留错误输出，不做解除读保护/全片擦除操作。

枚举网卡后，把有线口名称赋给变量。下列 GUID 是本机已枚举的 Realtek，换机重新选：

```powershell
$nic = '\Device\NPF_{52528361-DC95-49EC-95CF-1D2653888A6F}'
.\tools\master.ps1 -Action Scan -Interface $nic
.\tools\eeprom.ps1 -Action Info -Interface $nic
.\tools\eeprom.ps1 -Action Backup -Interface $nic -BackupPath 'evidence/logs/factory_sii.bin'
```

`Scan` 会请求 PREOP，记录从站数量、EEPROM 身份、AL 状态；退出请求 INIT，不使能模型。只连一块开发板。EEPROM 备份范围是 SII 头中声明的容量，不等于 EEPROM 芯片的全部物理容量。用 Info 输出核对容量/PDI/CRC，保留备份、丝印和输出。官方 eepromtool 示例即使失败也可能返回 0，本项目因此另查文件长度、CRC 和写后逐字节读回。

## 4. 保留当前 EEPROM，烧录配套固件

本块板出厂读取的身份：Vendor `0x000FDFFF`，Product `0x26483052`，Revision `0x00010000`。项目 ESI、SSC 与主站身份检查已调整为这组值；它是商家开发板身份，并非本项目注册的商业身份。

实测出厂 SII 为 2048 字节、CRC 正确，SPI PDI Control=`0x0E80`，Mailbox 起始地址 `0x1000/0x1080`、长度各 128。**当前正常通信不需要改写 EEPROM。** 项目固件通过 CoE 提供新的 12/12 字节 PDO，SOEM 读取对象字典并配置实际 SM/FMMU；出厂 SII 仍有旧 IO 的 1 字节 PDO/SM 描述。已验证的是此 SOEM 配置路径，尚未验证 TwinCAT 对该 SII/ESI 组合的处理。

构建仍生成 `build/config/EtherCAT_Joint_F407.sii.bin`（2048 字节），用于离线配置检查和后续可选实验，**未写入本板，也未验证其上电启动**。它按项目 ESI 生成，不能作为出厂备份。今后如需修改 EEPROM，先明确目的、保留本次原始备份，再由学习者显式执行写入；当前复现跳过 WriteProject。SOEM 本项目不在运行时解析 ESI XML。

接着使用 ST-LINK 烧录和校验：

```powershell
.\tools\flash.ps1
```

烧录器写入 `ethercat_joint.elf` 指定的 Flash 区并校验，复位启动。本工程 GNU 启动代码先初始化 data/bss，再 SystemInit、newlib 和 main；Flash 范围按 ZET6 的 512 KiB，普通 RAM 128 KiB，暂不用 CCM。

## 5. GDB 看懂板端

第一个终端：

```powershell
.\tools\debug-server.ps1
```

第二个终端仍在项目文件夹：

```powershell
.\tools\debug.ps1
```

GDB 已加载符号并连接 localhost:3333，复位暂停，临时断点 main。脚本不自动执行 `load`。按以下顺序观察：

```text
continue
tbreak Project_Poll
continue
print/x project_byte_test
print/x project_hw_cfg
x/3wx 0x40023800
x/wx 0x40000C28
print/x nAlStatus
print nPdInputSize
print nPdOutputSize
print model
print received_generation
```

实测 `BYTE_TEST=0x87654321`、`HW_CFG=0x08000000`（READY bit27 置位）；这些检查 SPI 与芯片就绪，不证明 EtherCAT 已到 OP。当前 ELF 中 `SystemCoreClock` 未保留符号，因此直接看 RCC_CR/PLLCFGR/CFGR：本次为 `0x03035e83/0x07405408/0x0000940a`，按商家 8MHz HSE 配置推算 SYSCLK=168MHz；TIM5 PSC=`0x53`，对应 84MHz 定时器时钟除以 84，计数 1MHz。这里是寄存器配置核对，没有用仪器测频。PDO 大小实测 12/12。SSC 保留原 TIM2 计时。

如果运行不到 `Project_Poll`，Ctrl+C 后 `bt` / `where`，查看是否卡在 `HW_Init`/SPI 的 busy 等待，再看 BYTE_TEST、PDI 和供电。若第一次 SPI 调用尚未完成，变量仍为 0；不能据此断言寄存器本身为 0。原厂 SPI busy 等待尚未加入全面的有界超时；应用看门狗要求主循环正常运行。

**运行真实周期通信时先删除循环断点并 continue。** 暂停 MCU 会改变通信时序并可能触发 ESC/应用超时，不能用暂停调试所得时间写实时指标。观察完可 `delete breakpoints`、`continue`、Ctrl+C 后 `detach`、`quit`；退出后让板正常运行或复位。

## 6. 真实主从通信

关闭其他占用网卡的 EtherCAT 主站；MCU 保持运行：

```powershell
.\tools\master.ps1 -Action Scan -Interface $nic
.\tools\master.ps1 -Action Inspect -Interface $nic
.\tools\master.ps1 -Action Demo -Interface $nic -ResetBeforeDemo -PeriodUs 10000 -Cycles 2000 -Csv 'evidence/logs/run01.csv'
```

`Inspect` 使用 SDO Upload 核对身份、支持模式、PDO 分配及每条映射，再读状态字、错误码和位置。`Demo` 限制为一个项目从站；身份/映射不匹配就拒绝输出，绝不拿商家 IO 的 2/6 字节映射试写关节。

正常演示预期：到 OP，按反馈逐步使能，CSP 到 +1000、-1000，快速停止，重新使能，注入 `FF01`，清除原因并 bit7 新上升沿复位，再使能 CSV=500，最后禁止。成功输出 `demo result=PASS`、`checks=0x3f`、保存实际 CSV；中止、阶段超时或 WKC 不符均返回失败/未完成。主站退出会尝试禁止并退到 INIT；断线情况下不能保证禁止帧送达，由板端负责超时停止。

下一次运行或中途暂停可能已有 `FF04` 锁存。核对原因后，示例中的 `-ResetBeforeDemo` 在本次 OP 会话内先显式复位，再推进演示；不加开关时不会复位已有故障。运行途中遇到意外故障仍会中止。仅需诊断复位、不运行运动序列时可以单独执行：

```powershell
.\tools\master.ps1 -Action Reset -Interface $nic
```

Reset 只复位到禁止接通，不使能、不沿用旧目标。不过该会话退出后停止 PDO，板端可再次锁存 FF04，因此不能依赖“单独 Reset，再启动另一个 Demo”来避免故障；重跑使用同会话的 `-ResetBeforeDemo`。

## 7. 拔线与数据分析

以下物理拔线实验尚未执行。运行 Demo 的 CSV 模式阶段时拔网线；`-Cycles` 是演示最大周期数，序列成功会提前结束，不能靠增大该值延长 CSV 阶段。主站应检测 WKC 异常停止使用反馈；板端设计为最后一次有效 PDO 接收后 100ms 锁存 `FF04`、速度归零。本次已观察主站退出后的超时故障与速度归零，但尚未实测物理拔线和精确阈值。观察需通过故障发生后的 GDB 或恢复后的 Inspect；拔线期间不能从已断开的 PDO 证明板端反馈。

插回后先 Scan/Inspect，确认故障仍锁存，再用 Demo 的 `-ResetBeforeDemo` 明确复位并演示。记录 ESC 最终状态、应用状态、错误码、最后接收时间、观察时间。应用超时与 ESC 看门狗谁先动作取决于实际主站/ESC 配置，不能预先把两个时间等同。

```powershell
& 'D:/apps/Python3.10.11/python.exe' tools/analyze_log.py evidence/logs/run01.csv
```

统计的是 PC 发包间隔与一次 send/receive 调用的耗时，包含主机调度和接收等待，不是从站控制 ISR 周期、DC 精度或线缆单程延迟。先用 10ms 把协议和状态通路验证，再尝试 5ms/2ms/1ms 并记录分布；Windows 普通线程没有硬实时保证。
