# 程序运行流程图

对照当前 main.c 阅读。第一张图看整段程序的正常执行顺序，第二张图展开一次 SDO 请求。第八课仍在学习中。

当前主站和从站是同一个 C 程序中的模拟角色，main 按顺序执行这些步骤；这不是两台设备之间的真实通信。程序只演示一轮，最后退出，没有 1 ms 循环。图中正常路径包括「按预期拒绝写入只读对象」；其他失败检查会让 main 提前 return 1。

## 1. main.c 从开始到结束

```mermaid
flowchart TD
    START(["进入 main"])
    INIT["初始化变量<br/>主站目标位置 2000，其他数据先置零"]
    STATE["第五课：请求状态依次切换<br/>INIT → PRE-OP → SAFE-OP → OP"]

    subgraph PDO["第六课：一次 PDO 命令与反馈交换"]
        P1["主站：EC_PackRxPDO<br/>将控制字、目标位置 2000 打包到 image.outputs"]
        P2["从站：EC_UnpackRxPDO<br/>从 image.outputs 解包，得到目标位置 2000"]
        P3["从站：模拟实际位置为 300<br/>EC_PackTxPDO 打包到 image.inputs"]
        P4["主站：EC_UnpackTxPDO<br/>读出实际位置 300"]
        P1 --> P2 --> P3 --> P4
    end

    subgraph OD["第七课：本地对象字典读写"]
        O1["从站：EC_OD_Init<br/>字典关联已有目标位置和实际位置变量"]
        O2["EC_OD_ReadI32<br/>读取目标位置 2000，再读取实际位置 300"]
        O3["EC_OD_WriteI32<br/>目标位置改为 4000"]
        O4["尝试写实际位置为 999<br/>返回 READ_ONLY，实际位置仍为 300"]
        O1 --> O2 --> O3 --> O4
    end

    subgraph SDO["第八课：通过模拟邮箱访问同一张字典"]
        S1["初始化邮箱与请求<br/>每次 EC_SDO_Transfer 都执行发送、处理、接收"]
        S2["主站请求 Upload 0x607A:00<br/>从站返回目标位置 4000"]
        S3["主站请求 Download 0x607A:00 = 5000<br/>从站更新目标位置，返回 OK"]
        S4["主站再次 Upload 0x607A:00<br/>从站返回目标位置 5000"]
        S5["主站请求 Download 0x6064:00 = 999<br/>从站返回 READ_ONLY，实际位置仍为 300"]
        S1 --> S2 --> S3 --> S4 --> S5
    end

    FINISH(["return 0，程序结束"])
    START --> INIT --> STATE --> P1
    P4 --> O1
    O4 --> S1
    S5 --> FINISH
```

这张图里的 PDO 和 SDO 是为了教学依次演示的两条数据路径，并不表示真实从站每个周期都必须先执行这几个字典测试，再执行四笔 SDO。

沿着图看 main 中相应的注释：准备阶段 → 第 1～4 步 → 第七课从这里开始 → 第八课从这里开始。每个阶段的 printf 都在对应操作之后，终端输出也按这个顺序出现。

## 2. 展开一次 EC_SDO_Transfer

下面是当前模拟器的函数调用顺序。参数完整、邮箱空闲时，Process 和 Receive 会依次成功；各函数还会独立检查自己的输入和邮箱状态。

```mermaid
flowchart TD
    T0["main 调用 EC_SDO_Transfer<br/>传入邮箱、字典、请求、响应接收变量"]
    T1{"四个指针是否非空？"}
    T2{"EC_Mailbox_Send<br/>邮箱是否为 EMPTY？"}
    FAIL["Transfer 返回 false<br/>本次未取得响应，main 提前退出"]
    SEND["复制主站请求到邮箱<br/>状态改为 REQUEST_READY"]
    PROCESS["EC_Mailbox_Process<br/>从站模拟角色取出请求"]
    SERVICE{"请求的 service 是什么？"}
    UP["Upload：调用 EC_OD_ReadI32<br/>读取对象，数值写入 response.value"]
    DOWN["Download：调用 EC_OD_WriteI32<br/>检查对象权限，允许时修改原变量"]
    INVALID["未知服务<br/>result = INVALID_ARGUMENT"]
    READY["将字典操作结果放入 response.result<br/>状态改为 RESPONSE_READY"]
    RECEIVE["EC_Mailbox_Receive<br/>把响应复制给主站接收变量"]
    EMPTY["状态恢复 EMPTY<br/>允许发送下一笔请求"]
    SUCCESS["Transfer 返回 true<br/>表示主站已取得响应"]
    CHECK["main 检查 response.result<br/>OK 表示操作成功<br/>READ_ONLY 表示写入被拒绝"]

    T0 --> T1
    T1 -- "否" --> FAIL
    T1 -- "是" --> T2
    T2 -- "否：上一笔事务还没结束" --> FAIL
    T2 -- "是" --> SEND --> PROCESS --> SERVICE
    SERVICE -- "UPLOAD" --> UP
    SERVICE -- "DOWNLOAD" --> DOWN
    SERVICE -- "其他" --> INVALID
    UP --> READY
    DOWN --> READY
    INVALID --> READY
    READY --> RECEIVE --> EMPTY --> SUCCESS --> CHECK
```

Process 或 Receive 的参数、状态检查失败时，Transfer 也会返回 false。这张图展开普通完整事务，不模拟网络超时或异步等待。

「Transfer 返回 true」和「response.result 为 OK」是两个判断：写只读对象时，从站正常生成拒绝响应，所以 Transfer 可以返回 true，同时 result 为 READ_ONLY。main 的最后一个演示正是在验证这个拒绝结果，按预期收到 READ_ONLY 后继续正常结束。

## 3. 用数字跟踪同一个目标变量

| 执行到哪里 | 从站目标位置 | 原因 |
|---|---|---|
| 程序初始化 | 0 | slave_command 初始化为零 |
| RxPDO 解包后 | 2000 | 收到主站命令 |
| 第七课字典写入后 | 4000 | 你完成的本地字典练习 |
| 第八课首次 Upload 后 | 4000 | 读取不修改变量 |
| 第八课 Download 后 | 5000 | 写请求通过字典修改同一变量 |
| 第八课再次 Upload 后 | 5000 | 读回修改后的数值 |

实际位置在模拟编码器赋值后一直是 300；两次尝试通过字典或 SDO 写成 999 都被拒绝。修改练习数值后，按相同执行顺序理解新的输出。
