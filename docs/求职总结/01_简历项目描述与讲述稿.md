## 5. 2 分钟项目介绍

我想往机器人和工业控制嵌入式软件方向发展，所以选择 EtherCAT 作为总线协议学习项目。工程分成两条：一条是 Windows 标准 C 模拟器，另一条是 SOEM 主站环境准备。

模拟器先处理过程数据：主站目标按显式小端格式变成 RxPDO 字节，从站解包得到应用变量，再把实际值编码成 TxPDO 返回。对象字典保存应用变量的指针，所以 PDO 更新的目标也能从 SDO 路径看到。SDO 部分模拟单事务邮箱和四字节快速传输内容，能解释正常读写、只读拒绝和错误响应。

我重点复习的一次排错是地址映射。修改本地起点要让 SM 与 FMMU 一致；逻辑起点又必须与主站请求匹配。只改映射配置，不改访问请求，会在数据进入应用前被拒绝。这让我把对象索引、逻辑地址和本地地址分清楚。

CiA402 部分用软件状态机演示 6、7、F 的正常使能路径，以及快速停止和故障复位。使能请求并不一定让状态进入 Operation Enabled，本地条件不满足仍保持 Switched On。故障处理中，要区分原因消失、处理完成和新的复位沿，复位成功也需要重新走使能路径。

工程还有三模式与看门狗参考例子，用于后续自主学习。软件代码有严格编译和异常场景验证，课程标签可以回顾每个阶段；但目前没有真实从站通信、电机闭环或实际 1 ms 性能数据。

若尚不能解释后两课，讲到第十一课即可；不要为了讲满时间认领还没读懂的内容。

## 6. 两个值得展开的技术问题

### 地址修改后为什么失败

可以这样回答：工程把映射规则与请求地址分开保存。FMMU 先检查整个逻辑访问区间，再换算 ESC 本地地址；SM 再检查本地地址、长度和访问方向。如果把映射逻辑起点改成 0x20，但请求仍从 0 开始，就会在 FMMU 阶段被拒绝。要迁移逻辑区间，配置、请求地址、越界演示和输出说明应一起调整。当前已保存的成果是本地起点 0x1020，逻辑起点仍为 0；逻辑迁移到 0x20 只做过失败分析，没有记录为完成练习。

### 请求使能后为什么仍未使能

可以这样回答：控制字表示请求，状态字表示从站当前状态。我把进入条件改成 false 后，最后一条 0x000F 已被识别，但驱动状态保持 Switched On，状态字是 0x0023。函数返回 true 表示支持并处理该输入，不能直接当作电机已经运行；通信 OP 也只是通信层许可。
