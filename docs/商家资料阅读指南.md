## 3 第一次接板前必须掌握的内容

先认识硬件和配置，再选择一套例程。所需资料主要集中在 `02`、`03` 和 `06`，不是那两本上千页的 STM32 手册。

### 硬件与 PDI

PDI 是 STM32 访问 LAN9252 的本地接口；它与 PC 到板子的 EtherCAT 网线不是一回事。资料表给出的 SPI 引脚如下，作为核对线索，不作为尚未确认板版本时的直接接线指令。

| 信号 | 表格标注的 STM32F407 引脚 | 用途 |
|---|---|---|
| SPI_CS | PA8 | SPI 片选，例程需核对软件控制方式 |
| SPI_MOSI / MISO / SCK | PA7 / PA6 / PA5 | SPI1 数据与时钟 |
| IRQ | PC0 | ESC 事件通知 |
| SYNC0 / SYNC1 | PC3 / PC1 | 同步信号，后续 DC 学习时重点看 |
| RST# | PF8 | 复位信号 |

上电前只需从原理图和实物确认供电入口、电压、SWD 和网口方向。原理图可见 USB_POWER、5V 与 3.3V 电源部分；资料没有替代实物板版本核对，不能据此给未知接口直接加电。无需现在通读电源、晶振、磁珠和电容的全部数据手册。

### 固件 ESI 与 EEPROM 的关系

固件决定实际对象字典、PDO 打包方式和硬件访问；ESI 是主站配置工具使用的 XML 设备说明；EEPROM 内保存 SII 二进制信息及 ESC 启动配置。配置工具可以依据 ESI 生成并写入相应 EEPROM 内容，EEPROM 并不是直接存放整份 XML 文本。[ETG 的 EEPROM 说明](https://prelive.ethercat.org/technology/knowledge-base/eeprom/)

因此每次选例程都要同时记下：PDI 类型、工程文件、配套 ESI、设备身份、PDO 大小及 EEPROM 来源。第一次接板先读取和记录现有身份与状态，确认出厂配置；不要仅因为教程出现“烧 EEPROM”就立即覆盖已有内容。

《烧写EEPROM的方法.pdf》只有 4 页，接板前看懂操作目标即可。实际写入时，需要先确定使用哪套固件和 XML，保留原配置的读取或备份记录；这是后续硬件实验的一个单独步骤。

### 主站选择

目前项目既定路线是 Windows + SOEM + Npcap，已枚举 Realtek 有线网卡。商家资料多数以 TwinCAT 为操作界面，可用于理解扫描、状态、PDO 与 EEPROM 更新，但不用为了读资料马上切换主站。

《twincat支持EtherCAT的intel 网卡列表（芯片型号）.docx》只在决定使用 TwinCAT 并核对其驱动时再看。它不是 SOEM 的网卡兼容性清单。SOEM 枚举成功也还不等于已验证你的真实 EtherCAT 收发能力。

## 4 代码压缩包怎么选

推荐先从 **SPI IO** 开始阅读，因为本项目后续迁移也关注 SPI。真正烧录前仍应确认实物 PDI 和卖家提供的出厂配置；若实物已配为 HBI/FSMC，先使用匹配的 IO 例程也可以。现在不要把接口切换本身变成第一项练习。

以下信息来自 ZIP 内部的工程与 XML 检查，未编译、未烧板。SM 大小是 ESI 的默认声明，实际运行值还需要与固件、映射及主站扫描核对。

| 代码包所在位置 | 包内配套 ESI | 声明的 SM2 输出 / SM3 输入 | 选择建议 |
|---|---|---|---|

| `06/EtherCAT_IO例程/IOl例程_FSMC_LED+按键+ADC+OLED显示（新手点灯例程）.zip` | `LAN9252-EVB-HBIXML.xml` | 2 / 6 字节 | 实物与 EEPROM 为 HBI/FSMC 时使用；不与 SPI 包混用 |
| `06/hal库代码/EtherCAT_从站_LAN9252_SPI_IO(从站代码).zip` | `YS-IO.xml` | 2 / 2 字节 | HAL 学习备选，配合该目录的入门手册；工程 `YS-F4STD.uvprojx` |
| `06/hal库代码/EtherCAT_从站_LAN9252_SPI_IO(从站代码)改SSC.zip` | `SSC-Device.xml` | 1 / 1 字节 | 学到 SSC 自动生成时再用；包内含生成源码与对象表 |
| `06/hal库代码/EtherCAT_LAN9252_SPI_ CIA402.zip` | `YQ-CIA402.xml` | 按该包映射核对 | 先跑通 IO，再做 CiA402；不能沿用 IO 包的 XML |
| `06/Cia402协议代码.zip` | `CiA402_9252-单轴.xml` | 默认 12 / 12 字节，含多组 PDO | 包内路径有 HBI，放到后续 CiA402 阶段 |

例程虽然都叫 LAN9252，设备身份也不全相同。例如标准库 SPI IO 的产品码为 `0x00009252`、修订为 `0x1`；HAL IO 的产品码为 `0x26483052`、修订为 `0x00020111`；改 SSC 包修订为 `0x00010000`，厂商字段也变了。**“都是 SPI”不足以证明 XML 可互换。**

### 源码只按这条线读

1. 打开工程 `.uvprojx`，确认实际参与编译的文件和配置宏。
2. 在应用源文件中找 `main`，读 `HW_Init → MainInit → MainLoop` 的主线。
3. 找 `APPL_OutputMapping`，理解主站输出怎样变成本地变量，即从站 RxPDO。
4. 找 `APPL_Application`，只追踪一个 LED 或按键。
5. 找 `APPL_InputMapping`，理解本地反馈怎样交给 ESC，即从站 TxPDO。
6. 再看对应对象字典头文件和 ESI，把索引、位长度、顺序对起来。
7. 最后查看 `el9800hw.c/.h` 及实际被调用的 LAN9252 驱动，理解硬件读写。

`Input/OutputMapping` 通常采用主站过程映像视角，Rx/Tx 则采用从站视角，因此名称看似反向，先画数据箭头即可。

**不要只凭 `main.c` 的文件名找入口。** 标准库 SPI IO 的工程 Src 组包含 `el9800appl.c`，其中有条件编译的入口；目录里另有 SRAM 测试 `main.c`。HAL 包的 `Src/main.c` 中入口也被注释了，应用入口由所选应用文件和宏决定。读到“怎么只有 SRAM 测试”或“main 全被注释”时，先回工程核对编译文件，不需要把这些残留文件立即改成新入口。

`ecatslv.c`、`mailbox.c`、`ecatcoe.c`、`sdoserv.c`、`objdef.c` 先只认识职责。等有具体问题再顺调用链深入，不要求现在逐行读完整协议栈。

## 7 旧资料里容易踩的坑

### 软件版本与历史教程

旧《EatherCAT开发板使用教程.pdf》和资料使用说明要求 Win7，还涉及旧安装顺序。将它们作为历史操作示例即可；不要直接据此重装系统、卸载安全软件或运行资料包里的安装程序。本次没有执行这些操作。

Beckhoff 当前官方系统要求列有 Windows 10/11，兼容性取决于 TwinCAT build、Engineering/Runtime 和硬件条件；这也不表示尚未检查的本机组合一定可运行。安装阶段再核对具体版本。[Beckhoff 系统要求](https://infosys.beckhoff.com/content/1033/tc3_overview/6162419083.html)

### 映射方向与长度

《开发板资料使用说明-R1.1.pdf》第 3 页把 TxPDO 与 0x16xx、0x1C12 联系在一起，文字方向写反。按从站视角，应采用以下对应关系；包内实际 ESI 也声明 RxPDO 在 SM2、TxPDO 在 SM3。

| 数据方向 | 从站名称 | 常见映射对象 | 常见分配对象 | 本资料例程使用的 SM |
|---|---|---|---|---|
| 主站发命令给从站 | RxPDO | 0x1600–0x17FF | 0x1C12 | SM2 |
| 从站反馈给主站 | TxPDO | 0x1A00–0x1BFF | 0x1C13 | SM3 |

文档中的“总长度必须是 16bit 的倍数”“添加必须以 2 字节为单位”要结合该例程的映射函数、填充和访问方式理解，不能推广成所有 EtherCAT PDO 的限制。改 SSC 包的 ESI 就声明 SM2/SM3 各 1 字节。声明不等于已验收：真正改映射时，仍需核对固件处理的长度、打包方式与 XML。

### 两种状态机与模拟电机

EtherCAT 的 INIT/PRE-OP/SAFE-OP/OP 管通信状态；CiA402 的 Switch On Disabled、Switched On、Operation Enabled 等管驱动状态。**进入 OP 不等于电机已使能，收到目标位置也不等于电机已经运动。** 这与当前第十课“请求和反馈独立”的重点一致，ETG6010 第 4 节末尾也明确区分两种状态机。

《Cia402调试教程.docx》的“必须运行在 DC 模式”针对它介绍的测试软件和模式；不要将一句例程要求理解成所有 CiA402 应用的统一条件。先理解例程的同步需求，再配置 DC。

已检查的 CiA402 源码含 `CiA402_DummyMotionControl`，通过目标、速度和周期计算模拟反馈。因此演示轴或数值变化不能作为真实电机闭环已实现的证据。后续关节控制仍需要单独实现和验证实际电机控制、采样、保护与故障处理。

同样，示例文件夹中“500us”“测试通过”等名称只是商家的命名。本次没有验证真实周期、实时性或通信结果。
